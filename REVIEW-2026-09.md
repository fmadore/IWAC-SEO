# IWAC SEO — module review, September 2026

Third full review of the module (1.1.1, 63 files under `src/`), following `ROADMAP.md`
(0.6/0.7) and `SEO-CITATION-AUDIT.md` (1.1). Scope: refactoring, efficiency and
practice across the code, the SEO layer against current search-engine guidance, and
the citation layer (formatted styles, BibTeX/biblatex, RIS, CSL-JSON, Zotero meta
tags and unAPI) against the style manuals and importer behaviour.

The architecture holds up. The 1.1 round fixed the large semantic losses the audit
found, and what remains is mostly narrower: formatting defects that only show on
particular record shapes, export fields that land where no consumer reads them, and
a few operational edges. The defects that could be confirmed and fixed without a
policy decision are fixed on this branch; everything else is below as a
recommendation, ordered by value.

## How this was checked

- Every file under `src/`, `config/`, `Module.php`, the views, scripts, workflows and
  tests was read. Suspected defects were reproduced against the real classes before
  being fixed, and each fix has a regression test that fails without it.
- `composer check` equivalents (i18n, PSR-12, PHPStan level 6, PHPUnit) and the Omeka
  S 4.2.1 integration suite were run locally on PHP 8.4 before and after the changes.
  Before: 160 unit tests / 665 assertions, 45 integration / 418. After: **173 / 711**
  and **47 / 434**, lint and analysis clean. The CI matrix (8.2–8.5) was not run.
- Omeka behaviour was read from the 4.2.1 source rather than assumed (job dispatch,
  timestamps, `siteUrl()`, the public item controller).
- Search-engine guidance was checked against current documentation. The sandbox could
  not reach `developers.google.com` directly, so Google's pages were consulted through
  search results that quote them; each claim below cites its source.
- No live Zotero Connector round trip, and no biber run, was possible here. The
  export changes follow the biblatex manual and Zotero's documented RIS mapping.

## Fixed on this branch

| Area | Defect | Fix |
|---|---|---|

| APA (fr) | `(2018, décembre 7)` — English order in French | `(2018, 7 décembre)`, the French adaptation's order |

## Recommendations acted on afterwards

Four groups of recommendations below were then implemented on the same branch:

| Recommendation | Done |
|---|---|
| SEO 1 — crawl control for query variants | `robots.txt` disallows the query variants of the IwacSearch pages (`/search`, `/recherche`, their `everything`/`tout` tabs, `/discovery/token`) and of Omeka's item, item-set and media browse, with `?page=` allowed. The rules are instance data (`iwac_seo.robots`); `RobotsTxt::allows()` applies Google's precedence, and a config test proves landing pages, pagination and every sitemap URL shape stay crawlable. IwacSearch was checked first: it renders its first results server-side and queries Typesense from the browser, so nothing the landing page needs is blocked. |
| Citations 4 — archive name | `iwac_seo.citation.archive_names`: *Collection Islam Afrique de l'Ouest* on the French site, *Islam West Africa Collection* on the English one. |
| Citations 5 — downloads | `/cite/{id}/{format}?site={slug}`, added by the "How to cite" panel: the file links the reader's site and reads in its language. The route is unchanged; without the parameter the default site answers. |
| Citations 3 (part) | `ZoteroRdf` takes `CitationData` by injection and serialises from the `CitationRecord`. Output is unchanged; the `rdf:Seq` creator lists still need a Zotero round trip. |
| Refactoring 1, 2, 3, 5, 7, 9 | Legacy queue path removed behind a `PingOutboxInterface`; a malformed `IWAC_SEO_PUBLIC_ORIGIN` is logged and ignored in page renders, reported on the dashboard and fatal to the cron script; `ResourceUrl` documents what `siteUrl()` does; dashboard previews are built per language by the controller, with translatable field labels; media and site edits invalidate the sitemap without pinging; the Google auth action is pinned to a commit. |
| Refactoring 4, 6 (part) | One `MonthNames` table; `CitationMeta` reads shared values once; `SiteResolver` memoises public-site lookups. |

Still open: SEO 2–7; Citations 1, 2, 3 (`rdf:Seq`), 6–10; Refactoring 4 (`isAudio()`
memoisation), 6 (lock files, id-range chunks), 8 (DBAL 3) and 10 (biber and
translation-server checks in CI).

## Recommendations

### SEO

1. **Stop crawling faceted search URLs rather than only noindexing them.** Google's
   faceted-navigation guidance (2024) says a `noindex` still has to be crawled to be
   read, and recommends a `robots.txt` disallow for filter URLs that need not be
   indexed. The 1.0.1 changelog records 1,306 IwacSearch `/search` variants in one
   Search Console report. Add `Disallow: /s/*/search?` (Google honours `*`), and
   consider the Omeka browse routes' filter parameters too, keeping `?page=` crawlable.
   Make it a setting or a config list, since it is policy. Confirm first that the
   search app does not render from URLs this would block.
2. **Image licence metadata for the scans and photographs.** Google Images shows a
   "Licensable" badge from `ImageObject` markup with `contentUrl` plus one of
   `license`, `acquireLicensePage`, `creditText`, `creator` or `copyrightNotice`. IWAC
   records carry RightsStatements.org statements in `dcterms:rights` (for example
   *In Copyright – Rights-Holder(s) Unlocatable or Unidentifiable*), which map to
   stable rightsstatements.org URIs for `license`, with the collection as
   `creditText`. Class 58 is already typed `ImageObject` but has no `contentUrl`.
3. **`max-image-preview:large`** in the robots meta of indexable pages. For a
   scan-heavy archive, large previews are what Discover and image results show. Emit it
   through `HeadWriter::robots()`, merged with any `noindex` rather than competing.
4. **Share-card accessibility and sizing.** Emit `og:image:alt` / `twitter:image:alt`
   from Omeka 4's media alt text (falling back to the title), and
   `og:image:width`/`height` where known.
5. **YouTube upload dates are a data task, not code.** 1.1 correctly stopped
   inventing `uploadDate`. The true value for the 1,745 YouTube-sourced records is
   the platform's `publishedAt` timestamp. Writing it into `dcterms:issued` in the
   IWAC data pipeline makes the existing code emit it, and makes those videos
   rich-result eligible.
6. **`priority` and `changefreq`.** Google documents that it ignores both, and
   uses `lastmod` only when it is consistently accurate. The depth-based priority
   machinery in `SitemapGenerator` is harmless but buys nothing with Google. Keep it
   only if another consumer is known to use it; otherwise delete it with its config.
7. **Broader JSON-LD context (low priority).** `isAccessibleForFree`, `license` (as
   in 2), and a `provider`/`sourceOrganization` for ZMO. `ArchiveComponent` with
   `holdingArchive` describes an archival item well for non-Google consumers. None of
   these affects a Google rich result.

### Citations, Zotero and BibTeX

1. **Emit `citation_author` as "Family, Given" from authority records.** Scholar
   accepts either order, and Zotero's Embedded Metadata splits on the comma.
   `CitationData` already has structured names; the meta tags still send display
   labels, which Zotero splits on the last space. That is wrong for multi-word
   surnames such as *Olivier de Sardan*, on every kind that does not go through
   unAPI (all bibliographic references). Do a Connector round trip before and after.
2. **Literal names with particles.** `Creator::parse()` files *Jean-Pierre Olivier
   de Sardan* under "Sardan". It only applies when no authority record supplies
   `foaf:lastName`. Either link those names to authorities, or teach the parser the
   common particles (*de, du, des, van, von, ben, ibn, ould …*) and keep them with
   the family name, as citeproc does.
3. **Let `ZoteroRdf` consume the record it already builds.** `render()` constructs
   `new CitationData(...)` (bypassing the container), then re-reads the title,
   creators, keywords, call number and PDF straight from the item. Inject
   `CitationData` and serialise from the `CitationRecord`. While there, emit authors
   and editors as `bib:authors`/`bib:editors` `rdf:Seq` lists of `foaf:Person` nodes,
   as Zotero's own RDF export does. Repeated `dcterms:creator` triples carry no order,
   and editors are currently literals that Zotero splits, institutions included.
4. **The archive name is hard-coded English instance data.** `CitationData` writes
   "Islam West Africa Collection" into every record, on the French site too. Move it
   to `instance.config.php`, localised per site ("Collection Islam Afrique de l'Ouest").
5. **Downloads ignore the site the reader is on.** `/cite/{id}/{format}` always
   builds the French (default-site) URL and selects the abstract without a locale.
   Pass the site slug from the view helper (for example `?site=westafrica`).
6. **Which URL a citation points at is a policy worth stating.** `link()` and every
   export prefer the original source URL (`fabio:hasURL`) over the IWAC page. For
   born-digital press the IWAC capture is the stable copy, and a source URL may rot
   (the dataset already contains Wayback captures). Consider the IWAC page as the
   primary URL with the source as a note, plus an access date (`urldate` /
   `accessed` / `Y2`) for MLA.
7. **Language codes.** `MetadataValue::language()` maps six languages; any other
   label (*Mooré*, *Dioula*, *Wolof* …) goes into `inLanguage`, CSL and RIS as free
   text where a BCP 47 code is expected. Extend the map from the actual
   `dcterms:language` labels in the catalogue (for example `mos`, `dyu`, `wo`, `bm`,
   `ff`, `dje`, `yo`).
8. **Replace the COinS roadmap item with unAPI on browse pages.** An
   `<abbr class="unapi-id">` per result on browse and search pages lets the Connector
   save a whole results page in one step, reusing the existing endpoint. COinS would
   add a third, weaker path.
9. **biblatex remainder.** `@periodical` has no `author` field (its responsible party
   is `editor`), so the issuing organisation is dropped by standard styles. `type` is
   emitted for every kind but only printed for thesis, report and misc-like types.
10. **Decide where archive fields belong.** `CitationData` sets the archive name for
    every record with an `iwac-` accession, bibliographic references included. The
    exports now carry it consistently (CSL `archive`/`archive_location`, RIS
    `DB`/`AN`/`CN`). Before this branch CSL already sent `archive` and RIS `AN` for
    every kind. CSL styles that print archive fields will cite "Islam West Africa
    Collection, iwac-…" after a published journal article, as they already did for
    the CSL download. The module's own formatter adds that line only for documents and
    photographs. If IWAC is the holding archive only for primary sources, scope the
    archive fields to those kinds in `CitationData` (the call number can stay on all).

### Refactoring and practice

1. **Remove `PingQueue`'s settings-backed legacy path.** `PingQueueFactory` always
   injects the repository, so `drain()`, `isBulk()`, the fallback in `push()` and the
   `PENDING` constant are dead outside tests. Make the repository non-nullable and
   delete them, with their tests.
2. **`UrlPolicy::publicUrl()` re-reads and re-validates the environment variable on
   every call**, and throws from inside view listeners. A malformed
   `IWAC_SEO_PUBLIC_ORIGIN` therefore turns every public page into a 500. Validate
   once, memoise, and fail loudly on the dashboard and in the cron script. In a page
   render, log and fall back instead.
3. **`ResourceUrl` documents a behaviour Omeka does not have.** It says `siteUrl()`
   throws for a resource not assigned to the site. In 4.2.1 it only assembles a route,
   and the public item controller does not check assignment either. Harmless for
   hreflang, since the alternate still renders, but the comment misleads.
4. **Duplicated month tables** in `CitationFormatter` and `VideoDescription`, and
   repeated reads: `CitationMeta` reads keywords, abstract and people twice each.
   `MetadataValue::isAudio()` walks the media list several times per class-38 page,
   because the kind map is consulted by four services. Memoise per resource id for
   the request.
5. **Admin view hygiene.** `dashboard.phtml` instantiates `CitationFormatter` itself,
   and its `@var` block omits `$citationPreview`, `$citationMissing` and
   `$queueCounts`. `CitationDiagnostics` returns English field names to a French admin.
6. **Sitemap cache details.** `SitemapController::indexAction()` runs a site API
   search for each language before the cache is consulted. Per-document `*.lock`
   files are never removed by `clear()`. Chunks are cut by `OFFSET`, so one
   insertion early in the id range changes every later file. Id-range chunks would
   be stable. None of this matters at the archive's ~25k records.
7. **Other invalidation gaps.** Media visibility edits (image entries) and site
   navigation or homepage edits (page order) wait out the 24-hour TTL. Invalidating
   from `MediaAdapter` and `SiteAdapter`, without pinging, would close both.
8. **DBAL forward compatibility.** `PingRepository::install()` uses
   `getSchemaManager()`, which is deprecated in DBAL 3 and removed in 4. That is fine
   on Omeka 4.2's DBAL 2.13; note it for the next Omeka major.
9. **Pin actions that hold credentials.** `google-github-actions/auth@v3` runs with
   `id-token: write` and is pinned to a mutable tag. GitHub's hardening guide
   recommends a commit SHA for such actions, and Dependabot is already configured to
   bump them.
10. **Two acceptance tests worth adding to CI.** A biber
    `--tool --validate-datamodel` pass over sample `.bib` exports would have caught
    the `@periodical` and `@misc` field problems. Zotero's translation-server (Docker)
    can import the RIS, BibTeX, CSL and RDF exports and assert the item types and
    fields, which is the round trip `OPERATIONS.md` notes has never been automated.
